Record the app AS-SHIPPED — real routes, real copy, real assets, quirks included. Deviations belong ONLY in "Normalize on Redesign" below.

> ```

It went unnoticed because `check-docs.sh` §4a resolved only `src/`- and `doc/`-prefixed paths until `spec/` was added to that check on 2026-09-08.

> 🔄 **SỬA 2026-09-06 — the whole "Copy source" column was wrong.** Every row below used to end with *"Hardcoded Vietnamese literals in the template … no i18n layer"*. An i18n runtime has since landed and **no template holds a user-facing sentence any more**: `@ngx-translate/core` is a declared dependency, `src/FE/src/app/core/i18n/` wires it, `src/FE/public/i18n/{vi,en}.json` each carry the same set of leaf keys, and `<app-language-switcher>` (`src/FE/src/app/shared/components/language-switcher/`) switches at runtime with the choice persisted. Route `title` values are translation keys too, not sentences. Count the keys rather than copying a number:
>
> ```bash
> ls src/FE/public/i18n/
> grep -c 'ngx-translate' src/FE/package.json
> ```
>
> The constraint is enforced, not merely intended: gate **G12** in `scripts/fe-gate.sh` fails on any Vietnamese diacritic in an `.html` template outside a comment. Its stated blind spot is hard-coded **English** — so "G12 is green" means no Vietnamese sentence survives in a template, not that every string is translated.
>
> This is the exact failure the design area exists to prevent: the sentence "no i18n layer" carried no `file:line`, so nothing in `check-docs.sh` could contradict it, and every screen spec and prompt pack downstream inherited it.
